# Архитектура Laparoskan

## Границы системы

Приложение работает локально. Источник изображения — выбранная пользователем серия DICOM КТ/МРТ или явно обозначенный синтетический демо-кейс. Исходные DICOM читаются без изменения; сохранённый кейс содержит отдельную копию объёма, геометрию, разметку и учебные результаты. Облачных вызовов для обработки изображений нет.

Пакет `laparoskan` разделён на следующие части:

| Модуль | Ответственность |
| --- | --- |
| `dicom.py` | Поиск серий по DICOM-заголовкам, проверка согласованности, загрузка выбранной серии через SimpleITK/GDCM |
| `geometry.py` | Преобразования индекса XYZ ↔ физической точки пациента LPS в миллиметрах |
| `case.py` | Объём, метаданные и целочисленная медицинская маска в памяти |
| `mpr.py` | Физически корректные аксиальные, сагиттальные и корональные срезы |
| `segmentation.py` | Редактирование исходной маски сегментации и производная VTK-поверхность для показа |
| `planning.py` | Геометрия иглы, проверки попадания, пересечения и расстояния по маскам |
| `persistence.py` | Сохранение и загрузка переносимого кейса |
| `ui.py` | Русский интерфейс Qt, который показывает результаты расчётов и принимает действия пользователя |

Имена модулей отражают текущую структуру разработки; окончательные публичные функции перечислены в исходном коде.

## Координаты и единицы

Единственная система для медицинских расчётов — DICOM patient **LPS**, единицы — **мм**. `ImageGeometry` хранит `origin_lps`, `spacing_xyz`, ортонормальную матрицу `direction_lps` и размер `size_xyz`. Матрица задана по строкам; её столбцы направлены вдоль осей воксельной сетки. Для непрерывного индекса `i = (x, y, z)`:

```text
physical_lps = origin_lps + direction_lps @ (i * spacing_xyz)
i = inverse(direction_lps) @ (physical_lps - origin_lps) / spacing_xyz
```

Массивы NumPy хранятся в порядке `[z, y, x]`; это явно отличается от аргументов индекса `(x, y, z)`. Допустимы отражённые оси с определителем матрицы −1. UI/VTK использует те же числовые координаты LPS для отображения, но модели VTK остаются **производными**: по сглаженным поверхностям нельзя вычислять глубину, расстояние, пересечение или попадание.

Положение среза DICOM `ImagePositionPatient` и ориентация `ImageOrientationPatient` вместе с `PixelSpacing` задают геометрию плоскости. `SliceThickness` — номинальная толщина, не шаг соседних центров. При импорте шаг по Z определяется проекцией разности `ImagePositionPatient` на нормаль к плоскости. Несогласованные шаги, положение, ориентация и размер серии должны вызывать явный отказ или предупреждение до реконструкции. Это соответствует [описанию плоскости изображения в стандарте DICOM](https://dicom.nema.org/medical/dicom/current/output/chtml/part03/sect_C.7.6.2.html).

## Данные и 3D

В `Case.volume` хранится исходный объём интенсивностей; `Case.segmentation` — `uint8` labelmap той же формы и физической сетки. Редактирование маски увеличивает `segmentation_revision`, чтобы пересоздать отображаемые поверхности и пересчитать выводы о траектории. Помимо кисти и порога, ограниченный 6-связный рост области использует диапазон HU вокруг выбранной точки и не перезаписывает другие метки. Срезы MPR строятся из физической плоскости в LPS с интерполяцией интенсивности; цветная разметка выборочно накладывается из исходного labelmap. VTK-поверхности нужны только для обзора и выбора видимых точек.

Планирование принимает две точки LPS. Все метрики берутся из медицинской геометрии и разметки. Близость входа к границе маски тела проверяется по открытым граничным вокселям с допуском в диагональ вокселя; это дискретная проверка разметки, а не подтверждение истинной кожной поверхности. Экспериментальные варианты входа выбираются из доступной границы маски и сортируются по числу пересечённых размеченных структур, консервативной оценке просвета и длине. Это объяснимый геометрический порядок, не клинический оптимум. Отсутствие размеченного сосуда или органа означает **неизвестный** риск для этой структуры; текст результата не должен трактоваться как клиническая гарантия.

Файл `.lapcase` содержит JSON-манифест и массивы NPY в ZIP. Перед извлечением проверяются состав и заявленные размеры архива, геометрия, типы и формы массивов; копирование ограничено по числу байтов. Открытая маска доступна для редактирования через copy-on-write memory map, а временные файлы освобождаются при закрытии кейса.

## Границы будущих модулей

Настоящее совмещение с УЗИ и аппаратное отслеживание не входят в текущую реализацию. Будущие `UltrasoundSource`, `TrackingSource` и `RegistrationEngine` должны возвращать преобразования в физическом пространстве с явной оценкой ошибок регистрации. Ни один такой интерфейс сейчас не имитирует работающий аппарат.

## Ограничения валидации

Синтетические тесты проверяют математику преобразований и планирования. Они не подтверждают диагностическую точность, корректность сегментации пациента или клиническую безопасность. Отдельно требуются контрольные DICOM-кейсы и выборочное сопоставление с независимым эталоном, например 3D Slicer.
